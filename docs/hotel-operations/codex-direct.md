# 临时 Codex 业务试跑说明

## 当前定位

2026-11-27，用户再次明确原定分工：ChatGPT 负责谋略与全局统筹，ClawX 负责管理执行，Codex 负责技术建设。
现行方向以[系统分工与接通工单](system-architecture.md)为准。

此前“直接使用 Codex”用于模型接入受阻时继续有限试跑。将其扩大成 Codex 长期接管酒店经营的交接内容已撤回；本页不再要求继续扩大携程、PMS 或其他业务任务。
保留现有岗位、模型、知识、工作区、恢复副本、任务记录和所有业务产物，完整功能目标继续沿用。

## 已有成果如何使用

- 现场回传显示，已有 Codex 携程岗位完成过文本任务闭环，之后完成实际后台读取与独立验收。
- 这些结果可作为业务需求、来源、交接格式和后续执行器接入的验收样例。
- 本仓库维护环境没有重新读取运营电脑上的原始截图、回执或验收文件。实际经营数据和认证信息继续留在授权的现场环境。
- 单项业务成功、文件与聊天持久化，不等于 ChatGPT、ClawX 和独立 Codex 技术执行端已连接，也不代替完整重启恢复验收。

## 当前继续做什么

由 Codex 技术岗处理模型接入报错及系统通道，复用[任务协议](protocol.md)、[岗位指令](roles.md)和已有桥接实现。
既有 Codex 聊天与 OpenClaw Agent 是不同执行对象，需要核实可用的适配方式和权限；不能直接把会话名称当成已绑定 Agent。

临时人工交接只说明某个子步骤可执行。最终系统应让 ChatGPT 实际发起任务、管理层记录和派发、执行器回传、独立验收，再由 ChatGPT 重新查询到状态，减少老板反复转发。

所有功能要求继续列在[完整功能矩阵](README.md#完整功能矩阵)，按已实现、已部署、已接通、已验收分别记录。后续经营工作按照恢复后的系统分工推进。
