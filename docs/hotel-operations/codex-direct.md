# 直接使用现有 Codex 酒店岗位

## 当前执行决定

2026-11-27，用户决定直接使用已有 Codex 酒店岗位，暂停 ClawX 安装和模型接入。
后续酒店任务以此决定为准；ClawX、OpenClaw 和 Gateway 不再是开始业务工作的前置条件。
保留已有岗位、模型、酒店资料、工作区、恢复副本和本分支代码，完整功能目标继续沿用。

这份文档是执行交接说明，不会安装软件、修改运营电脑或把 ClawX 的运行时自动转换成 Codex。
既有 ClawX 实现和测试仍有参考价值；直接 Codex 的实际能力需要在运营电脑上逐项验证。

## 现在已知的状态

- 用户已确认复用对象是现有 Codex 酒店岗位。
- 用户提供的现场报告显示：恢复副本已独立解包验证，原工作区已有改动得到保留。
- 现场报告显示：既有携程岗位完成过一次使用已提供脱敏资料的文本任务闭环，包括派发、回传、格式修正、验收记录和持久化重读。
- 上述是现场报告提供的证据；本仓库维护环境没有重新读取运营电脑上的副本、任务产物或后台。
- 真实后台读取、技术层面的只读权限和完整应用重启恢复尚未通过现场验收。

先读取现场已有记录；不要为了切换方向重新初始化酒店工作区或重复创建全部岗位。

## 功能如何延续

| 功能要求 | 直接 Codex 的执行方式 | 需要保留的验证边界 |
| --- | --- | --- |
| 总管与既有岗位 | 复用原会话、职责和项目上下文；由一个总管入口组织工作 | 跨岗位交接必须有真实工具回执；没有该能力时可在当前执行端按职责完成任务 |
| 酒店知识 | 复用已有房型、政策、指标、历史决策和资料目录，按任务读取 | 共享目录可访问不代表所有会话已读到最新版本 |
| 任务与结果 | 沿用任务 ID、门店、目标、输入、来源、执行记录、产物、缺项和验收条件 | 记录实际执行者与结果版本；自查不能记成独立复核 |
| 携程、PMS、竞对 | 使用当前实际可用且已授权的读取工具，或既有合法导出资料 | 核对门店、来源、时间、口径和样本量；历史截图不等于当前后台接通 |
| 财务与客服 | 分析已授权资料，交付差异说明、处理建议和可审核文案 | 付款、退款、对客发送等动作须对应具体授权及可用执行工具 |
| 抖音内容 | 保留四类主题、历史去重、完整制作包、分项评分、80 分门槛和人工发布记录 | 评分属于内容质量评估；实际生成的视频、后台发布和经营效果分别验收 |
| 审批与追溯 | 保留具体变更方案、前后值、版本、审批主体和执行证据 | 方案变化后旧批准不适用；提示词不能替代真实权限控制 |
| 定时与恢复 | 按实际 Codex 环境落实持久记录、调度、重试和恢复检查 | 不承诺退出应用或关闭电脑后仍执行；以选定运行环境的实测结果为准 |
| 看板、多店和自动协作 | 保留完整需求，复用现成业务规则，再按实际需要接入 Codex 执行方式 | 本分支 Electron/Gateway 逻辑不能直接当成已启用的 Codex 功能 |

[原完整功能矩阵](README.md#完整功能矩阵)继续作为需求清单；其“本分支实现”列描述 ClawX 代码，不代表直接 Codex 已全部启用。
[岗位指令](roles.md)和[任务协议](protocol.md)中的业务要求可复用；OpenClaw 专有运行字段应按实际执行环境映射，不能伪造会话或执行批次。

## 下一项真实工作

先继续已试跑的携程任务：读取原始资料及现场验收记录，核对相关漏斗指标的来源、统计时段、分子、分母和样本量，给出有证据支持的结论和可执行的小试验。
原因没有查明时保持“待验证”；只有汇总资料时明确资料日期和分析范围。

随后按现有资料和工具可用性推进 PMS 经营日报、兴城市竞对分析、抖音制作包以及财务和客服任务。
每次交付都包含结果、来源、产物位置、缺项和下一步；平台未接通的任务继续保留，不阻塞其他可完成任务。

## 可直接复制给运营电脑本地 Codex

```text
执行方向已调整：暂停 ClawX 安装、OpenClaw/Gateway 联调和第三方模型接入，直接使用这台电脑现有的 Codex 酒店岗位推进经营工作。保留原有全部功能目标。

1. 先读取本地项目说明、AGENTS.md、相关记忆和已有现场验收记录。沿用原岗位、模型、资料目录、恢复副本和已完成结果，保护已有改动，不重新初始化。
2. 由现有总管组织任务。若本机已有实际验证过的跨岗位派发工具，复用并保存回执；否则由当前执行端按职责完成工作，准确记录执行者，不虚构另一岗位已接单。
3. 先续做既有携程任务：核对原始数据来源、统计时段、分子、分母和样本量，解释能被证据支持的变化，提出一个可衡量的小试验。原因未确认就写待验证。
4. 数据优先使用已授权的实际读取工具或已有导出资料。没有后台访问能力时明确缺项；能完成的分析、文案、脚本和报表继续完成。
5. 使用现有任务记录机制，保存任务 ID、执行回执、结果版本、来源、产物路径、缺项和验收意见。复用先前已验证的回传与格式修正流程；没有独立复核者时只记录自查。
6. 保留携程、PMS、兴城市竞对、抖音、财务、客服、知识库、审批、定时、恢复、看板和多店的完整功能清单。区分已复用、待接通、待实现，不能因取消 ClawX 而删除需求。
7. 抖音保留完整制作字段、历史去重和 80 分质量门槛，交付供审核的制作包。调价、付款、退款、对客发送和发布须匹配具体方案的现有授权；没有授权时先把可审核结果做完。
8. 分别验证真实后台读取、工具权限、定时运行和重启恢复；未验证的如实标注。不要把提示词限制当成技术隔离，也不要把聊天记录留存当成完整故障恢复。
9. 不把 ClawX 接入失败作为酒店工作整体停止的理由；Codex 本身能否运行以当前实际访问和工具结果为准。若 Codex 也出现地区或登录错误，记录具体错误来源，按官方支持处理。
10. 直接开始可完成的下一项工作，最后给出本次产物、证据和真实阻塞。只有无法自行解决的必要信息才询问。
```

## 入口与地区可用性

直接使用 Codex 不依赖 ClawX。已有 Codex 的认证方式、工具、权限和使用额度以实际账户与环境为准，不因第三方接入失败就自动要求更换模型或添加 API Key。
改变执行入口不会改变服务地区要求；未经查看具体错误，不能判断报错来自 ClawX、提供商还是 OpenAI。

官方参考：[ChatGPT Work 与 Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex)、[支持的国家和地区](https://help.openai.com/en/articles/7947663-chatgpt-and-openai-api-supported-countries-and-territories)。
