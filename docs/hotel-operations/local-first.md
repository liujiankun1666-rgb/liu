# 本机先用与批次交接

2026-11-27 用户最新决定：接入方式受阻时更换方式，停止把云端直连作为整个系统交付的前提。本文件优先于历史联调交接中“继续登录 Platform、引用标签、查隧道权限”的下一步指令。

## 当前方式

| 组成 | 负责事项 | 本轮入口 |
| --- | --- | --- |
| ChatGPT | 讨论目标、判断可行性、整理批次任务单、复盘汇总 | 当前对话 |
| ClawX / OpenClaw | 任务账本、拆单、派发、结果、独立验收、审批记录 | 运营电脑已有“酒店总管”工作台，沿用已工作的 DeepSeek |
| Codex | 配置与程序问题、代码、测试、技术交接 | 已有本机技术端与 GitHub 草稿 PR |
| 老板 | 一次交接批次目标、审阅派发方案及具体重要经营动作 | 本机工作台 |

不需要所有组件都通过实时云端通道相互连接，才能使用已经具备条件的本机功能。当前人工批次交接与未来自动交接分别记录；完整功能清单保留，自动云端交接标为未启用。

## 用户如何操作

1. 与 ChatGPT 讨论本批目标，得到一份包含目标、已知输入、允许动作和验收标准的任务单。
2. 在已运行的 ClawX 打开“酒店总管”，选择“新建任务”。总管讨论可以用“和总管讨论”，但普通聊天不能当作已派单；实际任务须进入任务中心。
3. 将整份任务单交给总管分析。已有岗位未绑定或工具未接入时，仅补齐所需岗位与来源，不批量重建、不覆盖已有模型配置。
4. 总管返回分派方案后，在同一任务详情用“确认方案并派给现有 Agent”。此后由任务中心管理各子任务，不让老板逐个转发。
5. 批次结束后带回一份汇总供 ChatGPT 复盘；经营审批继续按实际具体动作呈现。

现有界面依据：`src/pages/Hotel/index.tsx`、`TaskEditor.tsx`、`TaskDetail.tsx`。本机实际安装是否包含这些界面由本机 Codex 核实；仓库中有实现不等于运营电脑已经部署。

## 可直接填写的批次任务单

```text
批次目标：
适用门店与时间范围：
本机已有资料/已授权数据来源：
允许动作：查询、分析、形成待审方案；具体业务写入另按已授权范围处理。
交付物：一份汇总，含关键事实、来源与时间、建议、未完成项、需要老板决定的事项和任务编号。
验收标准：逐条对应本批目标；缺数不能编造、缺项不能通过；已执行动作必须有回执。
执行安排：总管先返回可审阅分派方案，经现有确认流程后由 ClawX 管理各岗位；程序故障交 Codex 技术岗。
```

这是输入模板，不会自行创建任务、授予权限或开始排期。首批使用本机实际具备的来源，尚未接入的后台明确列出缺项；不把合成样例当作真实经营结果。

## GitHub 的用途

现有 GitHub 连接可以继续交接技术工单、代码、测试和 PR。当前仓库公开，真实经营报表、平台截图、客户资料、认证信息和业务原始证据留在本机。不要为省一次交接把它改成经营收件箱，也不新增轮询服务作为当前前提。

未来若用户重新需要手机对话直接自动派发，可单独评估已有可用的本机入口、私有异步交接或远程 MCP。那是新的可选改进，需真实测试后才声明自动化，不能再次阻塞本机使用。

## 交付与状态

- 按现场报告，DeepSeek 合成任务已跑通读取、回传、独立 accept/return 及正常重启恢复。它是本机可用的基础，不证明所有酒店后台已接入。
- 本机交付应给老板明确的打开方式、可以执行的岗位/数据来源和批次操作方法。
- 旧失败、真实缺项、审计和原技术任务 `needs_review` 保留，不能因暂停隧道而直接改成通过。
- 无需为本次文档与优先级调整再重复全套测试或长时间合成联调；仅在发现影响实际使用的具体问题时进行针对性修复验证。
