## 第一轮：只读识别实际环境

此轮不安装或启动新包、不重启 Gateway、不运行配置修复、不清理浏览器，也不覆盖任何 Agent 或模型。

| 检查项 | 需要记录的事实 |
| --- | --- |
| 电脑 | 操作系统、架构、当前登录用户、本机是否确为日常酒店运营设备 |
| ClawX | 设置页版本、当前进程实际程序路径、实际 `userData` 目录；源码运行时记录仓库与提交 |
| OpenClaw | 当前应用对应包的版本、目录和入口；避免把 PATH 上另一份 CLI 当成正在使用的运行时 |
| Gateway | 是否运行、实际进程和来源、端口、运行日志中的版本；包内版本不能代替运行进程证据 |
| 现有岗位 | Agent ID、名称、工作区引用、模型及工具范围；只读摘要，不输出密钥和完整认证文件 |
| 酒店后台 | 在实际已有浏览器会话中核对门店与登录有效性；未连接或有登录墙时如实记录 |
| 本地设置 | Gateway 自动启动、自动检查更新与自动下载设置；记录原值，不在识别阶段修改 |

已有内部读取入口为 `app:version`、`app:getPath('userData')`、`openclaw:status` 和 `openclaw:getConfigDir`。
通过现有应用工具或只读文件检查使用这些能力；不为读取状态向外提供 Host API/Gateway 令牌。
路径实现见 [`paths.ts`](../../electron/utils/paths.ts)，相关接口见 [`ipc-handlers.ts`](../../electron/main/ipc-handlers.ts)。

## 第二轮：保留原环境，再选择运行方式

1. 在运营电脑本地保留实际 Electron `userData`、用户主目录下 `.openclaw` 及其引用的外部 Agent 工作区恢复副本。
2. 记录副本位置、时间与恢复对应关系；保持本机访问限制，不上传凭据、浏览器会话或经营数据到仓库和聊天。
3. 保留原浏览器配置及登录状态；不重新创建全部 Agent、不覆盖模型列表、不把清理卸载作为安装前提。
4. 核对旧 ClawX/Gateway 的进程归属，按已有授权正常退出后再受控切换；不同时启动两个版本争用同一配置。
5. 使用上述固定提交或能够证明包含该提交的代码；记录安装包对应工作流与 SHA，不能仅凭文件名或版本号判断。
6. 核对自动更新：当前发布源仍是上游 OSS 与 `ValueCell-ai/ClawX`，不是此功能分支；避免联调版本被自动替换。

正常启动有仓库既有的同步行为：技能/插件安装或升级、工作区上下文合并，以及 Gateway 启动时的认证、Token 和浏览器配置同步。
关闭 Gateway 自动启动不会关闭全部启动副作用；不能承诺启动新包完全不触碰原配置。见 [`index.ts`](../../electron/main/index.ts) 与 [`config-sync.ts`](../../electron/gateway/config-sync.ts)。
新旧版本沿用同一 `appId` 和产品名，换安装目录不隔离数据；OpenClaw 配置仍从用户主目录读取。
`CLAWX_USER_DATA_DIR` 在 Electron 中只于 `CLAWX_E2E=1` 时生效，不是正常运营的通用隔离开关。
若必须完全不触碰原环境，先用独立操作系统用户或虚拟机验证；E2E 模式不能冒充真实运营接入。

## 安装包路径与发布边界

| 现有路径 | 现场选择 |
| --- | --- |
| Windows `Package Windows (Manual)` | 可指定准确 `ref`，产出 x64 NSIS 安装包工件并保留 7 天；`--publish never`，未配置 SignPath 步骤 |
| Windows `Windows Build Test` | 会提交 SignPath 签名请求，依赖签名权限；不是最小内部打包路径 |
| macOS `Release` | 不作为测试包触发：包含签名/公证，后续 OSS 发布没有仅限标签的保护，手动触发也可能覆盖发布渠道 |
| macOS 本地源码或构建 | 在已保护的环境运行准确提交；需要安装包时准备仅产工件的流程或受控本地构建，并核对签名/公证条件 |
| 已通过的 PR CI | 提供验证和测试工件，不等于已有可下载的现场安装包 |

Windows NSIS 安装器会处理旧进程、替换程序、修改 PATH，并尝试长路径设置和 Defender 排除项；不能当作无副作用解压。
卸载提供删除 AppData 的选项；保留环境时不要选择删除数据。仅构建工件不会访问运营电脑配置，安装和首次运行另有上述影响。
配置依据：[`electron-builder.yml`](../../electron-builder.yml)、[`installer.nsh`](../../scripts/installer.nsh)、[Windows 手动工作流](../../.github/workflows/package-win-manual.yml)、[Release 工作流](../../.github/workflows/release.yml)。
