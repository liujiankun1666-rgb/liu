# 系统分工与当前建设主线

## 当前决定：恢复三层职责

2026-11-27，用户再次明确：ChatGPT 负责谋略与全局统筹，ClawX 负责管理执行，Codex 负责技术建设。
用户希望主要与 ChatGPT 讨论目标和决策，由系统完成任务交接与状态回传；反复人工复制任务和结果不属于最终完成状态。

此前因模型接入受阻而采用的直接 Codex 业务试跑只作为临时执行方式，不能扩大为 Codex 长期接管酒店经营。
暂停扩大携程/PMS 等业务试跑；当前建设重点恢复为诊断连接阻塞、补齐系统通道、验证完整任务链。
已有岗位、模型、配置、恢复副本、业务成果和完整功能清单继续保留。

| 组成 | 负责的事情 | 实际控制边界 |
| --- | --- | --- |
| 老板 | 经营目标、预算、约束和具体重要经营变更的决定 | 授权以具体任务和方案为准 |
| ChatGPT | 讨论策略、核对可行性、确定优先级、组织系统建设、检查总体进度与结果 | 创建任务、查询状态和接收结果依赖真实接通的接口；不把统筹职责写成已经获得远程权限 |
| ClawX / OpenClaw | 保存任务、拆单与派发、管理业务岗位、处理回传、独立验收流程、审批记录、定时和异常 | 经营写入仍依赖相应工具、实际权限和具体授权；工作台中的状态必须有执行证据 |
| Codex 技术执行端 | 读代码、开发适配器、修复故障、测试、部署准备和恢复方案 | 不因连接受阻自动升级为长期业务总管；技术成果回到任务管理和验收流程 |
| 业务岗位 | 携程、PMS、收益竞对、抖音、财务、客服等专业任务 | 只操作已接通且获授权的数据与工具，返回来源、产物和缺项 |

ChatGPT 的总体判断与技术验收，不替代服务端独立验收机制或老板经营审批。现有共享桥接凭据不能修改这些权限。

## 必须分清的四个对象

1. **ClawX 应用**：界面、配置、任务工作台。
2. **OpenClaw/Gateway**：本分支当前采用的 Agent 运行时和派发协议。
3. **模型提供商与认证**：给执行岗位提供推理能力；某条模型认证失败不等于工作台只能弃用。
4. **Codex 技术执行端**：实际读写代码、运行测试的应用/CLI 等执行环境，须有独立的交接与权限验证。

ClawX 中的 OpenAI/Codex 模型配置，与接通独立 Codex 技术执行端是两件事。
本仓库有多个模型提供商定义，但具体账号、地区和模型是否可用须现场核实，不能据此保证任一替代模型可用。
地区错误目前缺少原始错误和发生阶段，不预判根因，不通过改入口或改提示词宣称地区限制已消除。

代码依据：[提供商定义](../../electron/shared/providers/registry.ts)、[OAuth 处理](../../electron/utils/browser-oauth.ts)、[执行权限检查](../../electron/services/hotel/execution-policy.ts)。

## 已有实现与真实缺口

| 链路 | 已有内容 | 尚需完成 |
| --- | --- | --- |
| ChatGPT ↔ 管理执行层 | 按门店限定的状态、建单、派发及普通结果回传接口；本机 stdio MCP 适配 | 当前聊天到运营电脑的真实认证连接；远程 HTTPS 接入层不在现有实现中 |
| 管理层 ↔ 业务执行器 | 从 OpenClaw 配置发现 Agent，通过 Gateway 派发并匹配任务/批次/会话 | 用户已有酒店岗位在 Codex 中，不能直接当成 OpenClaw Agent；需要核实可用适配方式与职责映射 |
| 管理层 ↔ Codex 技术执行端 | 技术岗位、关联技术工单和代码任务权限检查 | 独立 Codex 执行器接入及权限验证；不能删除现有检查来冒充接通 |
| 执行结果 ↔ 验收 ↔ ChatGPT | 持久任务、结果历史、独立验收、审批版本和桥接状态查询代码 | 一次从实际 ChatGPT 发起并重新读回状态的完整联调，以及实际断连、重复请求和重启检查 |

现有业务试跑成果是来源与执行能力的现场证据，可用作后续适配器验收样例；它们不能代替以上系统链路验收。
现场报告与本仓库直接验证分别记录，原始经营数据、平台日志、认证信息和运营电脑文件保留在实际授权环境，不提交公开仓库。

## 下一项技术工单：诊断阻塞并接通首条系统任务链

### 工作范围

1. 在实际运营电脑读取应用版本、运行时来源、已有岗位位置及可用执行工具，沿用已有保护与恢复记录。
2. 取得模型接入报错的准确阶段、原始错误码与脱敏摘要，区分应用启动、Gateway、浏览器认证/回调、模型请求及独立执行器。先完成无业务写入的最小诊断。
3. 分别记录 ChatGPT 到管理层、管理层到业务执行器、管理层到技术执行器的连接现状，避免把模型登录成功当成执行器绑定成功。
4. 复用已有任务协议、持久化、桥接、审查与审批机制，补齐经实际验证可用的接入；按客户端和提供商当前官方能力核实兼容性。
5. 保留现有 Codex 岗位的资料和试跑成果。需要映射职责时先明确实际执行器及接入方式，不批量重建岗位或覆盖账号配置。
6. 用一项不产生经营写入的脱敏样例完成系统验收，最后再恢复更大范围的业务自动化。

ClawX 是当前选定的管理执行层。若现场诊断证明必须替换组件，应先明确等价实现、功能差异和迁移影响，不能默默把职责并入 Codex 聊天。

### 完成标准

- 当前 ChatGPT 实际发起任务后，管理层能查询到同一任务 ID。
- 管理层记录真实执行批次、执行端身份和发送回执。
- 结果回到同一任务和批次，包含来源及产物，先进入待验收。
- 实际独立验收完成后，ChatGPT 能重新查询对应结果与验收状态；不用老板复制回传充当自动连接。
- 无效凭据、越门店请求和未经授权的经营写入会被拒绝。
- 断连、重复请求和重启分别留下实测结果；没有测试的项目明确标为未验证。

仅本机命令、模拟执行器或人工转发通过时，只能验收对应子链路；不得宣布整个系统接通。
