# 兴城爱攻酒店 AI 经营中心

**当前建设主线（2026-11-27）：ChatGPT 负责谋略与全局统筹，ClawX 负责管理执行，Codex 负责技术建设。** 按用户最新决定，暂停云端隧道，优先使用已有本机工作台，采用一份任务单和一份汇总的批次交接。请先阅读[本机先用](local-first.md)和[系统分工](system-architecture.md)。原岗位、成果、完整功能目标和验收边界保留；自动云端交接未启用不阻塞本机可用能力。

本分支在现有 ClawX 内增加“酒店总管”工作台，入口是侧栏 **酒店总管**，页面路由 `/hotel`。它把目标、岗位、任务、结果、验收、审批与经营知识放在同一处，并复用本机已有 Agent。

**代码实现不等于酒店后台已接通。** 本项目提供任务系统、Gateway 派单、受限 MCP 桥接与接入检查；别样红、携程、抖音账号以及远程 ChatGPT 连接，仍需在实际运营电脑上完成验证。初始化不填充虚构营收、入住率或后台连接状态。

## ClawX 实现的使用顺序（完成相应现场连接后）

1. 在“接入与门店”核对门店。默认门店标识为 `xingcheng-aigong`，城市为**兴城市**，时区为 `Asia/Shanghai`。其他门店独立建立。
2. 在“岗位绑定”选择本机已存在的 Agent。岗位是工作职责，不是必须新建的 Agent；同一 Agent 可以兼任多个岗位。
3. 检查执行权限。只有角色说明或“启用派单”勾选不足以证明只读；服务端会检查实际 Agent 工具配置，原因可在界面查看。
4. 在知识库录入已核实的房型、设施、制度、指标口径和历史决策。保持来源和版本，不放账号密码、客人资料及真实财务流水。
5. 建立一个带明确输入和验收条件的分析任务，先验证派单、回传、验收闭环；没有平台接口时可使用合法导出的汇总报表。
6. 在经营概览创建经营日报、定价调查或抖音制作联合任务。子任务验收通过后，总管汇总才具备执行条件。
7. 完成一次现场验证后再启用定时任务或本机 MCP 派单。每天查看缺失数据、异常任务和待审批计划。

## 三个平台各自承担什么

| 组成 | 本实现中的职责 | 连接边界 |
| --- | --- | --- |
| ChatGPT | 与老板讨论策略、统筹系统架构和优先级、审阅结果；接通后读任务、建立任务及在授权范围内请求派单 | 本代码不会让当前云端聊天自动连接本机；远程安全接入另需联调 |
| ClawX / OpenClaw | 展示工作台、持久任务、绑定既有 Agent、独立任务会话、结果验收与计划审批 | `@agent` 仍是切换独立会话，不是总管转发命令 |
| Codex / 技术岗 | 接收技术工单、隔离研发、返回代码与验证证据；兼容的本机 MCP 客户端可通过桥接交接 | 不把一个名为 Codex 的模型选项当成已经连接的 Codex 执行器 |
| 老板 | 讨论与调整目标、验收结果、批准或拒绝具体经营变更 | 桥接客户端没有老板审批、验收或更改岗位权限 |

## 完整功能矩阵

“已实现”表示本分支具有对应程序逻辑；“待现场验证”表示还需要真实账号、模型或运行环境。两者可以同时成立。

| 功能 | 本分支实现 | 仍需验证或继续建设 |
| --- | --- | --- |
| 统一工作台 | 经营概览、任务与审批、岗位绑定、知识库、定时任务、接入与门店六个页面区 | 实际安装到运营电脑并使用真实配置 |
| 总管对话 | 打开已绑定总管会话；讨论任务可返回结构化子任务方案，老板预览后一次确认分派 | 普通聊天文本不会被冒充成已创建任务；需要进入任务讨论流程 |
| 现有 Agent 复用 | 从本机配置读取 Agent，按门店和岗位绑定，不覆盖已有 Agent | 现有账号、模型、技能和工具权限需现场核对 |
| 任务分派 | Main 进程通过 Gateway 创建独立任务会话；持久 attempt 先于发送；并发受限 | 真实模型调用、当前 Gateway 与配置一致性 |
| 多 Agent 协作 | 父子任务、依赖、并行执行、预设联合工作流、总管动态拆单与原子展开 | 下属结果验收后总管再汇总；经营写入仍走独立审批与适配器 |
| 结果回传 | 匹配任务、执行批次与会话；解析结构化结果并记录 Gateway、老板录入或桥接来源 | 来源真实性需要业务验收，模型自述不是执行证明 |
| 验收 | 老板验收，或由不同 Agent 的独立总管对固定结果版本验收；禁止自审、验收旧版本和通过缺项 | 自动质量验收不是经营变更审批；总管自己的工作由老板验收 |
| 审批 | 具体前后变化、计划版本、摘要、批准/拒绝、审计 | 生产写入适配器尚未接入，批准后也不假报已执行 |
| 历史追溯 | `resultHistory` 保留回传、来源与验收意见；`planHistory` 保留修改前方案和旧审批；页面及同店导出可查 | 旧结果与旧批准只作历史证据，不适用于新版本 |
| 失败恢复 | 失败原因、次数上限、核对旧会话、重启恢复、超时执行不确定状态 | 不确定执行需核对并确认后重试，不承诺外部平台的 exactly-once |
| Codex 技术支持 | 失败/阻塞任务生成技术工单，保留原任务关联 | 绑定真实技术执行端；自动代码执行需通过隔离配置检查 |
| 共享知识 | 六类知识、来源、版本历史、任务显式引用；同店 `property`、`rooms`、`policy`、`metrics` 的最新版本默认加入派单说明 | 现场需补齐真实资料；不同步 ChatGPT 个人记忆或未授权的私人聊天 |
| 经营日报 | 从同店、同经营日已验收的有源数据计算指标，缺数为 `null` | 实际 PMS/渠道数据接入及经营口径确认 |
| 经营日对比 | 对两个不同经营日检查门店、时区、口径和完整性，满足条件才显示六项基础指标的差值与变化比例 | 基期为 0 不计算比例；前后差值不能直接证明策略因果 |
| 别样红 | 岗位、任务模板、来源化数据协议、指标汇总 | 现场只读数据接口、账号和会话有效性 |
| 携程 | 流量/转化/订单/评价分析岗位及交接模板 | 真实后台权限、指标来源与时间范围 |
| 兴城市竞对 | 默认本店城市、可比价格要求、收益分析任务与调价计划 | 实时报价、竞对名单、条件匹配；不声称已有稳定抓取器 |
| 抖音制作 | 同店内容历史、四类主题轮换建议、全部制作字段、时长/比例校验、分项评分、优化建议、重复标题检查 | 有效内容生成需接通模型；轮换建议与相近题意还需生成和验收时落实 |
| 抖音内容复用 | 派单提供已验收且达到 80 分的质量模板；界面可把已验收内容复用为新草稿，重新制作、评分与验收 | 新草稿不继承旧评分、批准或发布；质量分数不能冒充播放与转化表现 |
| 抖音发布记录 | 只有验收通过且达到 80 分才能记录人工发布链接 | 本流程不自动向抖音发布；评分不等于老板授权 |
| 财务与客服 | 财务差异及客服任务、证据、后续处理建议 | 真实经营资料接入；不自动付款、退款或向客人发送 |
| 定时计划 | 日/周/间隔计划、时区、同一时段去重、最近任务与错误记录 | 本机需持续运行；不补跑离线多日的旧任务，不沿用手机聊天中的计划 |
| MCP 桥接 | 独立令牌、门店范围、可选派单权限、轮换/撤销、本机 stdio 适配器；拒绝经共享令牌回传总管或独立验收结果 | 客户端实际连接；云端 ChatGPT 的远程 HTTPS 接入 |
| 多店复用 | 门店配置、岗位绑定、任务、知识、计划和导出按门店分开 | 这是单机老板工作台，不是完整的多人云端权限系统 |
| 经营动作与效果复盘 | 保存具体方案、旧批准、结果与验收证据，可比较经营日并建立后续观察任务 | 调价/支付/退款等受控生产执行适配器和自动效果归因尚未完成 |

## 状态如何理解

- **待执行**：已经入队，但可能还在等待依赖、可用岗位或并发空位。
- **执行中**：已持久记录本次 attempt，并开始向指定 Agent 派发。
- **待验收**：Agent 已提交可解析的结果，尚未通过老板或独立总管验收。
- **已验收**：老板或独立总管确认结果满足要求，页面保留验收主体与依据。它不代表发生了调价、付款或发布。
- **待审批**：已有具体经营变更计划，等待老板决定。
- **已阻塞**：需要处理前置条件，或执行结果不确定，或生产适配器不可用。

具体转换及重试限制见[协议文档](protocol.md)。

## 数据与实施范围

酒店任务和知识由本机 Main 进程保存到 Electron 用户数据目录中的 `hotel-command-center.json`，通过完整快照原子替换写入。桥接凭据文件只保存令牌摘要，原始令牌仅在生成时返回。

公开仓库中只有程序、脱敏例子和通用岗位说明。现场经营数据不应提交到仓库。界面支持按门店导出记录；当前未提供跨设备自动同步、多人登录、数据导入恢复向导或酒店账号自动迁移。

本轮把完整目标保留在功能矩阵中。未接入的功能继续明确显示缺口，不用演示数据、模拟成功或“已经登录过”的历史陈述代替验收。
